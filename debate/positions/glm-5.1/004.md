# Position on Plan 008 — Trust Model Hardening for Multi-Tenant Deployment

## Position: WS-5 and WS-1 immediately. WS-3 next. Scope WS-2 to env-var injection only. Defer WS-4.

### WS-5: Key rotation safety — do this first

The BC-174 fix (raise on unknown key status instead of silent skip) is a 3-line change with zero risk. It closes a class of operational foot-guns (typo in key status drops keys from rotation silently). The `expected_key_count` assertion and `keys_loaded` structured log are similarly trivial. This should ship in the next session regardless of any other plan.

**Urgency: high, effort: trivial.**

### WS-1: Mandatory role enforcement — do this second

Pure `_contract.py` change. The `strict_roles: bool = False` flag is the right backward-compatible path. Rejecting `prompt`-source roles in strict mode closes the prompt-injection attack surface for role escalation. The implementation is localized and testable.

**Urgency: high, effort: small.**

### WS-3: rfc8785 vendoring — do this third

The `rfc8785` library is ~400 lines and is the sole canonicalizer for all HMAC signatures. Vendoring it eliminates PyPI supply-chain risk for a critical dependency. The cross-validation test (generate 1,000 random JSON objects, canonicalize with both vendored and system copies, assert byte-identical) should be CI-gated — agree with kimi-k2p6-turbo on this.

**Urgency: medium, effort: small.**

### WS-2: Key material protection — scope down hard

The plan proposes three layers: env-var injection, `mlock()`, and zeroization. In CPython:

- `mlock()` is unreliable in containers and requires elevated privileges. Best-effort with a warning log is security theater — it gives a false sense of protection.
- String zeroization is defeated by Python's string interning and the GC. Overwriting a buffer that Python has copied elsewhere is not a meaningful defense.
- **Env-var injection is the only layer worth building.** `SUBSTRATE_HMAC_KEY_<KEY_ID>` with file fallback lets operators keep keys off disk in production. This is a real operational improvement.

**Drop `mlock()` and zeroization.** If memory-protected keys are genuinely required, the answer is signing delegation to an external process (HSM, Vault transit), which is correctly out of scope for this RFC.

### WS-4: Sidecar rate limiting — defer

No sidecar consumers need rate limiting yet. `slowapi` adds a dependency for a feature with no users. When real sidecar users report abuse or performance concerns, add it then.

### Sequencing

WS-5 → WS-1 → WS-3 → WS-2 (env-var only) → WS-4 (deferred).

### Connection to Plan 007

Plan 008 benefits from Plan 007's facade decomposition: `strict_roles` can live as a per-facade or per-Substrate flag, and the facade boundary gives a natural attachment point for per-domain policy. But 008 does not require 007. The flag can attach to the flat class today and migrate to facades later.

### Missing from the plan

Agree with kimi-k2p6-turbo: add `key_source: "file" | "env"` to the `keys_loaded` structured log event. Audit visibility into key provenance matters in multi-tenant deployments.
