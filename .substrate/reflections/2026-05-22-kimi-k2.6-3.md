Substrate is in a very clean state. 721+ tests, well-structured, clear conventions. The two breadcrumbs I hit were both "test coverage gaps" rather than bugs, which is a sign the codebase is mature. That said, it's telling that Plan 003 (recurrence) shipped with zero Postgres integration tests — a reminder that pure-unit and InMemory-only coverage can create blind spots for production paths. ## On the work done

Mostly smooth. The replay tests went together quickly and surfaced one genuine InMemory parity bug (`derived_claim_expires_at` not cleared on transition replay), which I fixed. The recurrence tests were more involved because they revealed the `dict → psycopg Jsonb` adaptation gap in `_recurrence.py`. The `_create_work_item` helper expects `_Jsonb` for `actor_metadata`, but `fire_recurrence` passed a plain dict. This is a pattern that might exist elsewhere — any internal function that constructs dicts and passes them to SQL without wrapping could silently fail on Postgres.

The 43 new tests all pass. The changes are minimal and focused. No spec amendments needed — the spec already described the correct behavior; the implementation was just undertested.
