# Session Reflection — 2026-07-01

**Work summary:** Conducted an in-depth adversarial review of the regista
codebase using four parallel reviewer subagents (Kimi, GLM, Nemotron, MiniMax),
each covering a different slice. Triaged 40+ findings, fixed 13 confirmed
new issues (not already tracked as BC-090 through BC-099), ran a second
adversarial review of the fixes, and addressed all high-priority feedback
from that review. 1367 tests pass, ruff clean.

---

## On the project

Regista's architecture is sound — event-sourced with a transactional
projection, schema-per-project isolation, and a global hash chain for
tamper-evidence. But the codebase has grown organically across 20+ plans,
and the seams show. The two append paths (`_events.py` vs `_event_store.py`)
remain a source of duplicated logic. The facade decomposition (Plan 007)
introduced a subtle desync between Regista and its facades that nobody
caught because the tests asserted the wrong behavior (copy-on-write rather
than shared-reference mutation). The strict_roles feature (Plan 008 WS-1)
was only partially implemented — it guarded the check behind `allowed_roles`,
defeating the entire purpose for transitions without role restrictions.

The most impactful finding was the idempotency gap: `check_idempotency`
compared only `actor_id` and `transition`, silently returning the old
event when a different payload was submitted with the same `event_id`.
This is a data-integrity risk — a retried request with corrupted data
would silently succeed with the old result. The fix required careful
handling of reserved transitions (which have internally-generated payloads
with non-deterministic fields like `link_id`).

## On the work done

The four-reviewer parallel approach was effective for coverage but
produced significant overlap with existing tracked work items (BC-090
through BC-099, BC-172, BC-194). About half the findings were already
known. The genuinely new findings clustered around three themes:
(1) incomplete validation/enforcement (strict_roles bypass, reserved
transition names, idempotency payload), (2) concurrency safety (lock
ordering, advisory locks, atomic key reload), and (3) defense-in-depth
(dead-letter DELETE-first, path traversal, UniqueViolation constraint
inspection).

The second-round adversarial review (Kimi + GLM) caught a critical
regression: my idempotency payload comparison would false-collide on
`append_transition_event` because the stored payload includes
`custom_fields_update` but the idempotency check passed the raw payload.
This was caught because the reviewers actually read the diff and traced
the data flow. The fix was to compute `stored_payload` before the
idempotency check.

I'm confident in the fixes that have direct test coverage. The
`KeySet` torn-read fix (snapshotting under lock) is correct but
hard to test without a stress harness. The `compose_workflow`
path traversal fix is defense-in-depth — the endpoint is admin-only,
but restricting to a configured `workflow_dir` is the right default.

## On what remains

- **BC-090 through BC-099** remain open and tracked. Several overlap
  with findings from this session's reviewers but were already known.
  The most critical is BC-090 (replay doesn't reconstruct claim state)
  and BC-194 (heartbeat coalescing mutates without events).
- **SSRF protection** was identified by the Nemotron reviewer for
  witness/webhook/TSA URLs. I did not implement this because it's
  a larger feature requiring IP validation infrastructure. Worth filing
  if not already tracked.
- **The `_RESERVED_TRANSITIONS` idempotency skip** is intentionally broad
  — it skips ALL payload comparison for reserved transitions. A more
  precise approach would define per-transition which fields are
  caller-supplied vs internally generated. This is a design improvement,
  not a bug.
- **The `agent-notes breadcrumb reconcile --apply`** failed with a
  migration error (schema 'regista' missing migration 35). This is a
  dogfooding issue — regista's own work-tracking schema is behind on
  migrations. Pre-existing, not caused by this session.

## Gaps to flag

- **`append_transition_event` still has two separate check_idempotency
  calls** (pre-check and UniqueViolation handler). Both now use
  `stored_payload`, but the duplication is a maintenance risk.
- **The `statement_timeout` reset in `_transition.py`** uses `finally`
  inside the validator block, which means if the validator raises a
  non-RegistaError exception, the timeout is reset but the exception
  propagates. This is correct but subtle.
- **The `KeySet._lock`** is a `threading.Lock`, not `RLock`. If
  `_maybe_reload` → `_load` is ever called from within a context that
  already holds the lock, it will deadlock. Currently no code path does
  this, but it's a footgun for future maintainers.
- **The sidecar `compose_workflow` endpoint** now requires `workflow_dir`
  to be configured. Existing deployments that don't set this will get 403
  on the endpoint. This is a breaking change for the sidecar API.
- **No test for the env-var key ID collision detection** in `_keys.py`.
  The code checks for collisions but there's no test exercising it.
