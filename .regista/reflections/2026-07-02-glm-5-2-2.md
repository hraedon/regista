## On the project

The no-comments rule is enforced consistently. The mypy strict ratchet (burndown list in pyproject.toml) is a good mechanism — new modules are automatically held to strict while old ones are quarantined. The migration system is clean and idempotent.

One thing that struck me: the production regista schema (which dogfoods its own work tracking) was at migration 037 while the code now ships 038. This is a deployment gap that should be automated — perhaps `provision --verify` (Plan 025 WI-2.2) will catch this when implemented.

## On the work done

The implementation was smooth — the patterns are well-established enough that I could follow them without reverse-engineering. The adversarial review was genuinely valuable: it caught a SQL injection (C1) that I would have missed in self-review, a race condition (C2) that the unique partial index now prevents at the DB level, and non-atomic rotation (H1) that would have caused key loss on crash. The credential leakage findings (H4/H5) were important — doctor error messages and `config show` were both leaking DSN passwords.

What I'm confident in: the config resolver, secret resolver, version surface — these are simple, well-tested, and follow existing patterns. The principal key registry is also solid after the review fixes — the `SELECT FOR UPDATE` + unique partial index + atomic rotation combination gives the non-repudiation guarantee teeth.

What I'd want a second pair of eyes on: the `_detect_prefix` function in `_secrets.py` — the heuristic for distinguishing file paths from literal values could be surprising in edge cases (e.g., a Windows path on Linux). The doctor's `_check_schema_version` opens a raw psycopg connection bypassing `ConnectionManager` — it's safe now (uses `Identifier`), but it's a pattern divergence that future code might copy incorrectly.

## Gaps to flag

- `_secrets.py:_detect_prefix` — the heuristic for bare paths vs. literal values is fragile; a value like `C:\\Users\\key.json` on Linux would be treated as literal. Document that `file:` prefix is required for paths containing colons.
- `_doctor.py` — opens raw psycopg connections instead of using `ConnectionManager`; this is intentional (doctor must work before a project is connected) but diverges from the pattern. The `validate_project_name` + `Identifier` usage is correct but a future maintainer might not know why the pattern diverges.
- `_principal_keys.py:_fetch_entry` — opens a separate transaction after insert to read back the row; could construct the entry from known values instead. Minor efficiency gap.
- `_config.py` — `require_ssl` parsing silently accepts typos (`"tru"` → `False`). Not critical but a user could think SSL is enabled when it isn't.
- `tests/test_principal_keys.py` — no concurrent registration test (would validate C2 fix). The unique partial index provides DB-level enforcement, but an integration test would be defense-in-depth.
- `tests/test_doctor.py` — `test_reachable_db_with_no_projects` doesn't assert on check statuses; it only checks `reachable` and `schema_version`. Should assert `db:reachable` is `ok`.
- The prod regista schema was missing migration 038 — applied during this session. Future migrations need to be applied to prod before agent-notes CLI operations work. WI-205 filed and resolved.
- `uv.lock` changed significantly (665 insertions) — this appears to be from adding the `[vault]` and `[azure]` extras to pyproject.toml. Should verify this doesn't pull in unwanted transitive deps.
