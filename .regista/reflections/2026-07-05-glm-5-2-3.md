# Session Reflection — 2026-07-05

**Work summary:** Finished Plan 028 (event-log segment sealing) and the Plan 027 AssuranceOps facade follow-up. Fixed a critical regression in `_verify_global_hash_chain` introduced by the prior session's rewrite — the function never initialized `current` to `genesis_events[0]`, causing all 13 global-chain tests to fail with false-positive orphan warnings. Added CLI `archive verify/list` subcommands, InMemory archive stub, and documented the timestamp-based selection limitation. Committed as `c6b05f3`.

---

## On the project

Regista's architecture is maturing well. The event-sourced model with a transactionally-consistent projection is clean, and the facade decomposition (Plan 007) keeps `__init__.py` manageable. The segment sealing design (Plan 028) fits naturally into the existing hash-chain model — segments are just verified ranges with a seal signature, and replay bridging is an extension of the existing chain walk. The main tension I see is between the `global_seq` sequence (`CACHE 100`) and the actual chain-link order established by `prev_global_event_hash`. Under concurrency these can diverge, which makes timestamp-based segment selection imperfect. The codebase documents this as a known limitation rather than trying to solve it fully, which is the right call for now.

## On the work done

The critical fix was satisfyingly simple: the prior session's rewrite of `_verify_global_hash_chain` added segment bridging logic but dropped the `current = genesis_events[0]` initialization that the original had. The while loop immediately hit `if current is None: break` and exited, marking every event as an orphan. One line fix, 13 test failures resolved.

The CLI verify/list subcommands were straightforward to add following the existing `archive seal` pattern. The InMemory archive stub raises `NotImplementedError` — this is honest rather than pretending to support something it can't. The docs/retention.md known-limitation section about timestamp-based selection under concurrency is important context for operators.

I'm confident in the segment sealing implementation — the tests cover genesis segments, non-genesis segments, multi-segment replay bridging, seal signature verification, and nonexistent segment errors. The `_verify_global_chain` function in `_archive_segments.py` correctly builds a link_map keyed by `prev_global_event_hash` hex (empty string for None), identifies chain-start heads as events whose prev matches the anchor_hash, and walks to the tail.

## On what remains

- **Physical archival integration:** `archive_events` moves events to `events_archive` but doesn't set `archived = TRUE` on segment records or coordinate with segment sealing. This is the next logical step for Plan 028.
- **Sidecar routes:** No HTTP endpoints for seal/verify/list_segments yet. Low priority since CLI covers the operator workflow.
- **Segment deletion / retention TTL:** No mechanism to remove segments and their archived events after a retention period.
- **WI-008 (open):** Event signing delegation chain — an agent actor cannot be bound to an authorizing principal. This is a deeper trust-model issue.
- **BC-300 (open):** Global chain hash (`prev_global_event_hash`) is never verified during replay — actually, the code now does verify it, but the breadcrumb may need updating.
- **071 (critical):** Heartbeat revives expired claims (zombie revival) — this is a separate critical bug.

## Gaps to flag

- **`_verify_global_hash_chain` complexity:** The function at `_replay.py:65-244` is now ~180 lines with nested while-loop logic for segment bridging. It works but is hard to reason about. A future refactor could extract the segment-bridging into a helper.
- **Timestamp-based selection limitation:** Under high concurrency with `CACHE 100`, `global_seq` order can diverge from chain-link order. Sealing very small segments under sustained concurrent load could produce segments with chain breaks. Documented in `docs/retention.md` but not enforced.
- **`pyproject.toml` mypy burndown:** `_archive_segments.py` is added to the `ignore_errors` mypy burndown list. This is technical debt — the module should eventually be typed properly.
- **No sidecar routes for segment operations:** The HTTP API is incomplete compared to the CLI. Operators using the sidecar can't seal/verify/list segments.
- **`_in_memory.py:151-155` — archive stub raises `NotImplementedError`:** This means any test that accesses `sub.archive` on an InMemory instance will get a runtime error. No tests currently do this, but it's a sharp edge.
