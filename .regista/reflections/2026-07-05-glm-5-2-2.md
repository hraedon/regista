## On the project

The review assurance design (Plan 027) is a principled response to the single-model deployment problem. Instead of pretending that Claude-reviewing-Claude is independent review, the system records the reviewer's lineage and computes an honest assurance level. The strict gate profile is a workflow-level policy that requires human accept when review is same-lineage — a compensating control, not a guarantee of quality. The architecture is clean: `AssuranceLevel` is a pure function of the event log, stored nowhere mutable, so it can never disagree with the record. When a second model arrives, items automatically start reaching `INDEPENDENTLY_REVIEWED` with zero schema change.

The Windows DPAPI provider was the missing piece of Plan 025's secret backend. The implementation uses `CRYPTPROTECT_LOCAL_MACHINE` scope, which works in any session type — including SSH, where Credential Manager and user-scope DPAPI both fail because the user profile isn't loaded. The hybrid ctypes→.NET/PowerShell fallback is pragmatic: ctypes is the fast path (no subprocess), but it fails on machines where the DPAPI key isn't accessible (Python 3.14 ctypes issue or session limitation). The .NET fallback via PowerShell is slow but reliable — it works everywhere .NET is installed.

The `_detect_prefix` fix was a pre-existing bug: `vault:foo` without `hvac` installed silently resolved as `literal:"vault:foo"`, returning the string as bytes instead of raising an error. The fix adds `_KNOWN_PROVIDER_NAMES` so known-but-unregistered prefixes raise `SECRET_RESOLVE_FAILED`. This is a backward-incompatible behavior change, but the old behavior was a silent bug, not a feature.

## On the work done

The Plan 027 implementation was delegated to a general subagent, which produced a solid first pass: `_assurance.py` with all the right types and functions, `_review_validators.py` update, canonical workflow strict variant, CLI, sidecar, docs, and 65 tests. The adversarial review (kimi) then caught a critical correctness bug: `compute_assurance_level` used the last `accept` event in the entire history, ignoring reopen cycles. If an item was accepted, reopened, and re-reviewed, the stale accept from the first cycle would be used. Fixed by only considering accepts after the last `adversarial_pass` index. Added 3 reopen-cycle tests.

The Windows DPAPI testing was the most time-consuming part. Credential Manager (CredWriteW/CredReadW) fails with error 1312 (ERROR_NO_SUCH_LOGON_SESSION) in SSH sessions — this is a known Windows limitation where network logon sessions (type 3) don't have credential stores. DPAPI's `CryptProtectData` also fails with the same error via ctypes, but works via .NET/PowerShell. The hybrid approach (try ctypes, fall back to .NET) was verified with a round-trip test on mvmcitest01: encryption falls back to .NET (ctypes fails), decryption succeeds via ctypes (the .NET-encrypted blob is decryptable by ctypes since both use the machine key).

The kimi adversarial review was thorough and caught real issues. Beyond the critical stale-accept bug, it identified:
- Invalid `GateProfile` raising `ValueError` instead of `RegistaError` — fixed by wrapping in try/except
- DPAPI error messages leaking `stderr` — fixed by sanitizing
- `_win_dpapi_cache` thread safety — fixed with `threading.Lock`
- `canonical_workflow_yaml(strict=True)` being fragile string surgery — acknowledged but kept (tested, documented, fails loudly if pattern not found)

I'm confident in the assurance computation logic after the reopen-cycle fix. The Windows DPAPI provider works correctly as verified on the actual Windows machine. The test import fix is straightforward and eliminates a class of CI fragility.

## On what remains

- **Plan 027 WI-2.2 (gate decision recorded in transition payload):** The `gate_rationale` function computes the reason `done` was permitted, but it's not yet embedded in the `accept` transition's payload. This would require the consumer (agent-notes/dossier) to include the rationale when calling `transition()`. The computation is available; embedding it is a consumer-side change.
- **Plan 027 WI-3.1 (docs + consumer references):** `docs/review-assurance.md` exists, but consumers (dossier, agent-notes) don't yet reference it.
- **AssuranceOps facade:** The review noted that `compute_assurance` and `gate_rationale` are only on the top-level `Regista`/`InMemoryRegista`, not in the ops facade layer. This is a consistency issue with Plan 007's decomposition.
- **`canonical_workflow_yaml(strict=True)` string surgery:** The kimi review flagged this as fragile. A proper YAML parse→mutate→re-emit approach would be more robust, but the current implementation is tested and fails loudly if the pattern isn't found.
- **Windows Credential Manager:** The original plan mentioned "DPAPI-protected blob via Credential Manager." Credential Manager doesn't work in SSH sessions. The current implementation uses DPAPI directly (without Credential Manager). Credential Manager support could be added as a second mode (`windows:cred:target_name`) for interactive sessions, but it's not blocking.
- **`windows = []` empty extra in pyproject.toml:** The review noted this is harmless but potentially confusing. It's there to match the plan's language about `[windows]` extra, even though no external dependency is needed (ctypes is stdlib).

## Gaps to flag

- `src/regista/_secrets.py:_dpapi_unprotect_dotnet` — uses `subprocess.run(["powershell", ...])` which spawns a PowerShell process per call. This is acceptable for startup-time resolution but would be slow if called frequently. Consider caching the result or using a persistent PowerShell process.
- `src/regista/_secrets.py:_dpapi_protect_dotnet` — same subprocess overhead for the encryption side.
- `src/regista/_assurance.py:gate_rationale` — the `profile` parameter now accepts `GateProfile | str` and validates, but the sidecar route (`src/regista/sidecar/routes.py`) still passes the raw query parameter string without Pydantic validation. An invalid profile string will now get a `RegistaError(INVALID_ARGUMENT)` instead of a 500, but the sidecar should map this to 400 explicitly.
- `src/regista/_workflow.py:canonical_workflow_yaml(strict=True)` — string replacement of YAML is fragile. If the canonical workflow YAML's indentation or field order changes, the replacement will silently produce the relaxed variant instead of strict. The test `test_strict_adds_require_human_on_same_lineage` catches this, but only after the fact.
- `tests/test_assurance.py` — no test for the `gate_rationale` with invalid profile string. The fix was added but not tested.
- `docs/review-assurance.md` — needs to be cross-referenced from AGENTS.md's source layout.
- `CHANGELOG.md` — not updated for the `_detect_prefix` breaking change (known-but-unregistered providers now raise instead of silently falling through to literal).
- `_win_dpapi_cache` — the thread-safe lock was added, but `protect_windows_secret` still calls both `_dpapi_protect_ctypes` and `_dpapi_protect_dotnet` without any caching of the result. If called repeatedly with the same input, it will encrypt each time.
