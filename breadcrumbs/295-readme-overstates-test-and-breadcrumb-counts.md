## Problem

`README.md:6` badge and `README.md:343` claim "992 tests passing" and "274
breadcrumbs tracked, 270 resolved." The resolved-BC-276 note in
`breadcrumbs/README.md` already says "All 1051 tests pass" — so the headline
992 is stale even by the repo's own internal record. (`grep "def test"`
counts ~913 test *functions*, which parametrization/classes multiply; the point
is the published number is a hand-maintained figure that has already drifted.)

Hardcoded counts in prose drift silently and erode the honesty signal the
project otherwise cultivates (e.g. the BC-192 honest-contract comment). Per the
project's own watch-metric (self-caught over-claims), a stale
"992 tests / 270 resolved" is exactly the kind of small over-claim worth
catching.

## Suggested fix

Replace the hardcoded test badge with one generated by CI, and drop the exact
"992" / "274 / 270" figures from prose (or regenerate them from
`agent-notes` / `pytest --collect-only` at release time). State capabilities,
not counts.
