# Position on Plan 007 — Public API Facade Decomposition

## Position: Do it now. No deprecation window. Internal decomposition is already done; the facade is a thin property layer.

### Why the timing is right

The internal modules (`_workflow_api.py`, `_work_items_api.py`, `_claims_api.py`, `_events_api.py`, `_links_api.py`, `_recurrence_api.py`) already exist and handle the delegation. The `__init__.py` methods are thin wrappers over these modules. Adding facade properties is a 1-session job because the hard work (extraction) is done.

Waiting for Plan 008 (trust model hardening) as kimi-k2p6-turbo suggests is unnecessary. Plan 008's `strict_roles` flag can attach to the facade objects just as easily as it attaches to the current flat methods. There is no dependency.

### Agree with kimi-k2p6-turbo on the mechanics

1. **No deprecation warnings.** We are the sole consumer. A `DeprecationWarning` per method is noise for zero benefit.
2. **Keep `transition()` and `replay()` on top-level `Substrate`.** These are orchestration-level operations. Moving `transition()` to a facade creates a circular dependency with claims, hooks, and events. It belongs where it is.
3. **Keep lifecycle methods (`create_project`, `close`, `connection_info`, `ensure_event_partitions`) on top-level.**
4. **Update all tests and examples in the same PR.** No mixed-mode codebase.
5. **Update sidecar routes immediately.** The sidecar does 1:1 mapping; it should consume facades natively.

### Disagree with kimi-k2p6-turbo on sequencing

kimi-k2p6-turbo recommends "after Plan 008." This is backwards. Plan 007 is a pure refactoring that simplifies the codebase. Plan 008 adds policy hooks. Building policy hooks on a clean facade structure is easier than building them on the current flat class and then migrating. **007 first, then 008.**

### Facade caching

Each property access should return the same facade instance (cached on first access via a `_facade_cache` dict). The facades are stateless — they hold references to the shared `ConnectionManager`, `KeySet`, and metrics registry — so caching is safe and avoids per-call allocation.

### Target shape

```python
class Substrate:
    @property
    def workflows(self) -> WorkflowOps: ...
    @property
    def work_items(self) -> WorkItemOps: ...
    @property
    def events(self) -> EventOps: ...
    @property
    def claims(self) -> ClaimOps: ...
    @property
    def hooks(self) -> HookOps: ...
    @property
    def links(self) -> LinkOps: ...
    @property
    def recurrence(self) -> RecurrenceOps: ...

    # Top-level (orchestration + lifecycle)
    def transition(self, ...): ...
    def replay(self, ...) -> ReplayReport: ...
    def create_project(cls, ...): ...
    def close(self): ...
    def ensure_event_partitions(self, ...): ...
    @property
    def connection_info(self) -> ConnectionInfo: ...
```

### Risk

The only real risk is that the facade pattern ossifies before Plan 008's per-domain policy needs are known. Mitigated by: facades are thin delegation layers. If Plan 008 needs a `strict_roles` flag on `WorkItemOps`, it's a constructor parameter on the facade, not a redesign.

### `__init__.py` after decomposition

Target: ~200 lines. Lifecycle methods + `transition()` + `replay()` + facade property accessors + `__init__`. Every domain method moves to its facade class.
