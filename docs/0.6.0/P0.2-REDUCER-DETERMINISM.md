**VERDICT: PASS. Signed review verdicts are GO for P3.2** — conditional on the two defects below
staying fixed, which the committed conformance test enforces.

`IMPLEMENTATION-PLAN.md` P0.2 asks for one thing: *a committed conformance test proving
byte-identity across at least two interpreters, or the negative result recorded and P3.2 cut.*
This is the record of the positive result.

**Why the frozen-digest shape.** A test that compares interpreters at runtime can only prove
what happens to be installed. Freezing the agreed digests and asserting them makes CI's existing
3.13 + 3.14 matrix a standing two-interpreter agreement check, and makes any future interpreter
that disagrees a build failure rather than a second, silently-minted digest. The sweep remains
for deliberate re-freezes, which invalidate every verdict signed against the old digests and
should feel like it.

Reproduce:

```
python3 tools/reducer_v1_sweep.py --sweep python3.12 python3.13 python3.14 pypy3.11
pytest tests/test_reducer_v1_determinism.py
```

## 2. The two defects found

L2 was right to flag this. The assumption was **false as the code stood** — in two independent
ways, both found by running the vectors rather than by reading the code.

### Defect 1 — `datetime.fromisoformat` is not a stable grammar across interpreters

`"2026-08-09T24:00:00Z"` is legal ISO 8601 (end-of-day). Measured:

| Interpreter | `datetime.fromisoformat("2026-08-09T24:00:00Z")` |
|---|---|
| CPython 3.14.4 | `2026-08-10T00:00:00+00:00` |
| CPython 3.13.14 | `ValueError` |
| CPython 3.12.13 | `ValueError` |
| PyPy 3.11.15 | `ValueError` |

On its own that is a portability wart. What makes it a **security** defect is what replay does
next: `_replay._parse_not_before` catches the `ValueError`, logs a warning, and substitutes
`None`. So the same signed prefix reduces to `not_before = 2026-08-10T00:00:00Z` on one host and
`not_before = None` on another — two different reduced states, two different
`content_state_digest` values, and a verdict that verifies on the machine that signed it and
reads as **stale** everywhere else. Nothing in the verifier's output says why.

That is precisely the failure mode a content binding exists to prevent, arriving through the
parser rather than through an attacker.

**Fix.** Reducer v1 parses RFC 3339 with an explicit grammar — mandatory offset, no week dates,
no ordinal dates, no basic format, no `24:00`, no leap second, no bare date, no naive timestamp —
and **fails closed** on anything else. Acceptance becomes a property of the specification instead
of the runtime. Sub-microsecond digits truncate rather than round, because rounding at
`…:59.9999999Z` carries into the next second and every implementation would have to make that
call identically without being told to.

### Defect 2 — a signable, canonical event whose digest cannot be computed

JCS serialises numbers in ES6 form, which prints any float below `1e21` **without an exponent**.
So the float `1e16` canonicalises to the integer literal `10000000000000000`. Parse those
canonical bytes back and you hold an integer of 10^16 — outside JCS's safe integer domain — which
**cannot be canonicalised again**.

Measured band: floats with `2**53 <= |v| < 1e21`. At or above `1e21`, ES6 switches to exponential
form and the value round-trips. Below `2**53` the integer is inside the safe domain.

```
1e15  -> {"x":1000000000000000}      re-canonicalises: OK
2**53 -> {"x":9007199254740992}      re-canonicalises: IntegerDomainError
1e16  -> {"x":10000000000000000}     re-canonicalises: IntegerDomainError
1e20  -> {"x":100000000000000000000} re-canonicalises: IntegerDomainError
1e21  -> {"x":1e+21}                 re-canonicalises: OK
```

`V6-ENVELOPE.md` §2.5 as frozen bounded *integers* at `±(2**53 - 1)` and left floats to the
canonicalizer, so a client writing `{"estimate_ns": 1e16}` into `custom_fields` produces a
perfectly valid signed event with **no computable subject digest** — for anyone, ever. No review
verdict can bind to that item.

**Fix.** One magnitude rule for both types: `|v| < 2**53`. `V6-ENVELOPE.md` §2.5 is amended
accordingly (P0.1 doc, updated 2026-08-09), and reducer v1 enforces it at parse. The whole
large-magnitude region is rejected rather than the exact band: the precise rule needs a case
analysis over the exponential-form threshold, and a rule two independent implementations must
reproduce identically should be one comparison.

## 3. What reducer v1 is

```text
content_state_digest = SHA256(
    b"regista.review-subject.state.v1\x00" || JCS(reduce_v1(E[0..k]))
)
```

- **Input:** canonical signed envelope bytes for one entity's chain in **chain order**
  (predecessor-link traversal — never `global_seq`), plus the workflow definitions carried by
  signed `workflow_registered` events (`V6-ENVELOPE.md` §1.9).
- **No database.** No `workflow_registry` row, no projection table, no psycopg. Enforced by an
  AST test over the module's imports: stdlib plus the vendored canonicalizer, nothing else. An
  offline auditor holding only a bundle must reach the same answer, or the binding is not
  checkable and therefore is not a binding.
- **Fails closed everywhere replay fails soft.** An unparseable timestamp, an unregistered
  workflow, a transition invalid from the current state, a duplicate object key, `NaN`, a
  non-UTF-8 byte — all raise. Replay is right to warn and continue; a digest cannot.
- **`reducer_version` is inside the reduced object**, so it is inside the digest. A future v2
  reducer cannot silently emit a v1 digest.

### The one open decision, deliberately left open

`include_claim_state` selects the field set:

| Value | Reduced fields | Consequence |
|---|---|---|
| `True` (strict) | + `claimed_by`, `claim_expires_at`, `claim_coalesce_threshold`, `attempt_number` | A claim, heartbeat or lease expiry stales the verdict. Literal reading of "stale after any state-changing event" |
| `False` | content only | Lease churn does not invalidate a review |

**Both are proved byte-stable across all four interpreters.** This is an operational call for the
owner — how much lease churn the estate's items see — and it explicitly **cannot reopen Gate 0**,
which is why it was built as a parameter rather than resolved by whoever implemented it.

## 4. What this does not prove

Stated plainly, because a determinism result invites over-reading.

1. **Four interpreters is not every interpreter.** It is CPython 3.12–3.14 and PyPy 3.11 on one
   Linux host. A non-Python verifier — the one an independent auditor would actually write — has
   not been tested against these vectors. The vectors are the artifact that makes that possible;
   nobody has done it yet.
2. **It proves the reduction is stable, not that the reduced field set is the right one.**
   §3's open decision is real, and so is the question of whether `custom_fields` should
   participate at all.
3. **It says nothing about the reducer matching replay.** Reducer v1 deliberately diverges from
   `_replay._replay_work_item` — it fails closed where replay warns. If P3.2 later wants
   "the verdict binds what replay computed", that equivalence is a separate proof and it will
   fail on exactly the inputs above.
4. **No signature was verified anywhere in this work.** The reducer consumes envelope bytes as
   given. Reaching it at all requires `verify_event_strict` to have passed first
   (`REVIEW-VERDICTS.md` §4.1 rule 1); nothing here substitutes for that.
5. **The 24:00 divergence is fixed in reducer v1, not in replay.** `_replay._parse_not_before`
   still swallows the `ValueError`, and so does `_in_memory_replay`. That is defensible for a
   projection rebuild — but the two now disagree by design, and anything that later assumes they
   agree is wrong. Worth its own work item.
